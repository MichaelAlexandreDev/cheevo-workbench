# Notas de estudo

Resumo do que foi feito em cada etapa e subetapa do roadmap, para estudar depois. Escrito em
português de propósito (o resto da documentação do projeto é em inglês).

Cada subetapa segue o mesmo formato:

- **O que foi feito**: o resultado, em poucas linhas.
- **Conceitos**: o que você precisa entender para ler o código.
- **Arquivos para ler**: em ordem, do mais importante para o menos.
- **O que aprendemos com a referência**: o que olhamos em `reference/` e o que decidimos diferente.
- **Problemas encontrados**: erros que apareceram e como foram resolvidos.
- **Para fixar**: perguntas e exercícios curtos. Tente responder sem olhar o código.

Quando uma **etapa inteira** termina, o arquivo dela ganha no topo um **Resumo da etapa**, para
ver o todo antes dos detalhes:

- **O que a etapa entregou**: o que o programa passou a fazer, do ponto de vista de quem usa.
- **Mapa do código**: os arquivos/classes da etapa e como se conectam (um diagrama simples).
- **O caminho de um frame** (ou do fluxo principal da etapa): o que acontece, em ordem, passando
  por cada peça.
- **Os conceitos mais importantes**: os 5–8 que você precisa dominar, com link para a subetapa.
- **Lições das revisões**: os bugs que as revisões e os testes pegaram e o que eles ensinam.
- **Prova da etapa**: perguntas que juntam várias subetapas, para checar se o todo fez sentido.
